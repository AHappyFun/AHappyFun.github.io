Base-RTX全光追与混合光追全景

#原理

“这款游戏支持光线追踪”这句话，在 2018 年是卖点，到 2026 年已经接近默认配置。但同样一句”支持光追”，Portal RTX 和 Cyberpunk 2077 的差别不在画质选项上，而在渲染架构：一个整帧由路径追踪生成，另一个只是把光照接到了路径追踪上。

这篇先把当前（2026-10）PC 端的路径追踪游戏分成两档，再挑三款代表作把管线拆开看。表里的分档依据不是”光追效果开了几个”，而是相机射线走哪条路——这条线比任何参数表都更能说明一个游戏到底”全”到什么程度。

它和 Base-渲染方案演进总览 里的 GI 演进线互为补充：那篇讲方案是怎么一步步来的，这篇讲 2026 年的游戏实际用了哪一套。

0. 分档标准：相机射线走哪条路

渲染一帧，本质上是回答两个问题：哪个表面被相机看到（主可见性），以及这个表面收到多少光（光照）。

光栅化的本质，是只处理”从相机出发、正好落在屏幕像素上”的那一束射线——深度缓冲帮你排好序，但除此之外的光路它一概不管。路径追踪则从相机出发，每条路径随机弹射，直到命中光源，阴影、反射、间接光一次算完。

于是分档只需要问三个问题：

问题 A 档：整帧路径追踪 B 档：混合全光追
相机射线（主可见性） 在 BVH 里求交，路径追踪器自己出首击 光栅化 G-buffer 出首击
光照 路径追踪统一出直接光、间接光、反射、阴影 路径追踪接管光照，替代多个独立 RT pass
光栅管线残留 只剩 UI、粒子、后处理这类非世界几何 整套 G-buffer、材质、几何管线都还在

一句话记法：A 档没有 G-buffer，B 档有。

顺带排掉一个命名陷阱：NVIDIA 官方口径把路径追踪叫作 “path tracing, also known as full ray tracing“。所以厂商通稿里的全称 “Full Ray Tracing” 大多落在 B 档，和”全”字没有关系。

1. A 档：整帧路径追踪

这一类数量少，因为要求游戏把整个光栅渲染器换掉，通常只有重制项目做得到。

3. 几个边界案例

  • Minecraft Bedrock：光照（含发光方块、水面折射）全走 PT，但它是”PT 光照 + 光栅主可见性”的极端混合体，按定义更靠近 B 与 A 的交界；放在 A 档的理由是画面里几乎没有传统光栅光照的残留。
  • Metro Exodus EE：4A 自称 “path tracing inside a hybrid renderer”——只有间接光走 PT，直接光仍是解析式光照 + shadow map，是 B 档的原型（见第 6 节）。
  • War Thunder / Enlisted：只把 GI 交给路径追踪，属于”最轻 B 档”。
  • 巫妖 3 的路径追踪：技术上是 B 档，但首发画质口碑反而输给老 RT 预设——档位高不等于好看。
  • 主机端：目前没有任何主机版提供路径追踪，A/B 两档实质都是 PC 独占；PS5 Pro 追加的也只是 RT 效果（2077 在 2026-04 的 Ray Tracing Pro 模式补了 RT 天光与自发光照明）。

4. 解剖一：Portal RTX —— 把 2007 年的引擎重写成路径追踪

4.1 Remix 的拦截式改造

RTX Remix 不是”给老游戏加个光追开关”，而是一个runtime + toolkit 的双件套：

  • runtime 坐在游戏和图形驱动之间，拦截游戏的 DirectX 8/9 绘制命令，把其中描述的场景重建出来，再交给现代路径追踪器渲染；
  • toolkit 给 modder 用来抓场景快照、替换网格 / PBR 材质 / 灯光，存成 mod 由 runtime 在下次启动时加载。

因为 runtime 是按”每个资产被画出来的那一刻”识别的，替换一个木桶或一面墙的材质，会出现在所有用到它的地方，modder 不需要改游戏本体文件。反过来，这套机制只能吃固定功能管线：越往后 DirectX 9 游戏越是用可编程着色器把信息藏起来，适配成本就越高；DirectX 10 以后直接不支持。所以 Remix 重制是”一游戏一项目”，不是一个按钮。

4.2 为什么它算 A 档

原来的光栅渲染器被整个换掉了——相机射线也进了 BVH，首击由路径追踪器自己算。画面里剩下的光栅部件只有 UI、粒子、后处理这些不属于世界几何的东西。按第 0 节的三问，三问全过。

4.3 传送门的递归在 PT 里反而变简单了

光栅时代，Portal 的”透过门看到另一个房间”要靠 stencil 或 portal camera 反复重绘：画一遍门后的场景，再把结果贴到门面上，嵌套传送门就得递归几层。到了路径追踪，这件事退化成一条穿过门平面的路径：光线打到门面，按门的变换折到另一侧继续走，末端自然带回另一间房的光照。反射、折射、门的嵌套都用同一套代码，不需要为传送门写特例——这也是为什么 Portal RTX 适合当 demo：它的核心玩法恰好是 PT 最擅长的递归追踪。

4.4 采样、降噪与代价

实时 PT 只给每像素一两个样本，靠时域累积 + 空间降噪把噪声抹平；Portal RTX 支持 DLSS 3 与 Ray Reconstruction，用神经降噪器替代传统降噪链路，同时提供超分来把帧率拉回来。代价有两层：一是性能，Remix 化之后的负载和现代 PT 大作同档，二十年前的游戏照样要新卡 + 超分；二是资产，原来的低模、平材质在真实光照下会原形毕露，所以 Remix 重制必须重做资产——这也是它慢的根本原因，不是因为光追难，而是因为光追会把旧资产的短板照出来。

5. 解剖二：2077 RT Overdrive —— 四个 RT pass 合成一个 path tracer

5.1 之前：四个互相不知情的 pass

2077 的标准 RT 档（1.5/1.6x 时期）把光追拆成四个独立效果：RT 阴影、RT 反射、RT 漫反射 GI、RT AO。每个 pass 有自己的采样策略、自己的降噪器、自己的近似。结果就是”不一致”：霓虹灯在湿地面反射里亮着，在阴影里却没贡献；光追 AO 和光追 GI 各自算一遍遮蔽，还可能互相打架。

5.2 Overdrive：一次算完

2023-04-11 的 1.62 补丁加入 Ray Tracing: Overdrive（技术预览），把上面四个 pass 换成一个路径追踪器：直接光、弹射光、反射出自同一次计算，所以彼此自洽——霓虹灯照亮街道、出现在水洼里、投下阴影，三件事是同一份光照的三个投影。

5.3 怎么跑得动

三件事叠起来才可行：

  1. 低样本：每像素只取一两个样本，剩下靠时间累积；
  2. 重采样：ReSTIR 复用邻像素和历史帧的光源选择，让每个像素只测最可能重要的光源（CD PROJEKT RED 与 NVIDIA 在 2023 年 ReSTIR 课程里讲过 Overdrive 的集成方案）；
  3. 降噪：先用 NRD 一类时域降噪，2023-09 的 2.0 更新后可以换成 DLSS Ray Reconstruction，用神经模型替代整条降噪链。

5.4 为什么它仍属 B 档

因为 G-buffer 还在：可见性、材质、法线仍由光栅化给出，路径追踪从 G-buffer 的表面出发去追次级光线。粒子、后处理、UI 也不在 PT 里。换句话说，Overdrive 换掉的是”光照怎么来”，没换”表面怎么被看见”——和 4A 给混合渲染器下的定义完全一致。

5.5 代价与瑕疵

Overdrive 至今仍是最重的画质选项之一，不开超分基本没法玩。低样本路径追踪的典型副作用它都有：暗部低频噪声、运动中的拖影、光源突变后要几帧才收敛。这些不是 bug，是”用时间换样本”的必然结果，也是降噪器质量的直接体现。

6. 解剖三：地铁离乡 EE —— “混合渲染器里的路径追踪”

6.1 2019 原版：一个 bounce、只有太阳

初版 Metro Exodus 的 RTGI 只处理阳光被场景几何散射后的二次交互：每像素从光栅化得到的表面位置和法线出发，打一条漫反射采样射线，命中点用 N-dot-L（太阳）+ 天空采样照亮，其余靠降噪抹平。之前用的体素网格 GI（从反射阴影图传输光照）被删掉，SSAO 也因为”遮蔽自然形成”而被移除。

这里有个关键细节值得记住：相机射线仍然是光栅化算的。4A 自己写的——“我们仍然用光栅化确定从相机射出的主射线，把光追和光栅结合的系统就叫混合渲染器”。

6.2 EE 的四步升级

  1. 光源数量：从”每个样本只有太阳 + 天空”变成每样本最多 256 个解析光源（spot/radial，各自带 shadow map 提供二次遮蔽），用世界空间网格做 light cluster 剔除——和延迟渲染里的屏幕空间光源剔除几乎同构，只是划分的是世界而非屏幕。
  2. 自发光几何：从 DLC 开始，被采样的表面可以是自发光材质，等于把面光源塞进 GI，得到解析光照 + shadow map 做不到的极软直接阴影。
  3. 简化材质：被采样的表面只用块状平均色，甚至不加载贴图，省带宽——反正这些表面不会被相机直接看到。
  4. DDGI：真正的”路径追踪感”来自这一步。二次以上的弹射交给世界空间探针网格 DDGI（基于 RTXGI SDK 的着色器技术），每帧采样并缓存，且读上一帧的 DDGI 结果——用时间累积模拟光在环境里反复弹射，给暗部补上单次弹射到不了的微弱提亮。

6.3 降噪输出的是球谐

4A 与 NVIDIA 联合开发的降噪链，输出不是一张图，而是一组球谐系数（亮度 + 色度）。球谐的主轴编码了入射光的主方向，所以除了粗糙的环境色，还能反推出一个粗糙的镜面反射——相当于自动生成了一张低精度反射 cubemap 的近似。

6.4 为什么停在 B 档

4A 的原文很直接：主射线仍走光栅、直接光仍是解析式光照 + shadow map；PC EE 另外加了镜面 RTR，但在能省的地方仍回落 SSR。所以 RayTraceDB 把它记成 RTGI 而不是路径追踪游戏——它的 PT 只发生在”间接光”这一段链条上。

6.5 性能账

这套改造的开销并不全是新增：删掉 SSAO、删掉旧 GI 近似，抵消了一部分 RTGI 与降噪的成本。这也是 EE 能作为免费升级、且在老卡上仍然可玩的原因。

8. 结论

  • 分档看架构，不看效果数量。一个游戏可以在”9 项效果里占 7 项”却仍是 B 档，也可以只开 4 项却是 A 档——差别在相机射线有没有被接管。
  • A 档稀缺不是技术不行，是场景不允许。现代 3A 的资产、LOD、粒子、后处理全是为光栅管线设计的，整帧 PT 等于把它们全部重做；老游戏反而便宜，因为它们的场景描述简单到 Remix 能完整截获。
  • B 档是当前 3A 的唯一可行解：保留光栅的几何与材质，把最难的那部分——光照的一致性——交给路径追踪。代价是每帧仍要为 G-buffer 付一遍光栅的钱。
  • “全实时”是预算分配，不是免费升级。巫妖 3 的路径追踪首发口碑翻车就是提醒：档位是架构标签，不是画质保证。
