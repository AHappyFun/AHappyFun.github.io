Base-技术美术素材与工具库

#游戏开发 #美术

做技术美术的日常里，有一半时间不是在「写」，而是在「找」：找一组能覆盖各种材质特性的测试模型来验证导入器，找一张真实世界的反射率数据来校准材质，找一套能批量下载 HDRI 的工具。这类资源单独看都不复杂，但散落在几十个仓库和站点里，每次要重新搜一遍。

下面按用途整理一批实际会反复用到的仓库和站点：测试模型与规格验证、纹理压缩、PBR 贴图与参数、HDRI、DCC 工作流插件、通用游戏资产，以及绕不开的几个外部资源站。学习路线和方法类资源另见 Base-技术美术学习资源。

素材类资源比教程多一层风险：许可证。教程用错了顶多白读，素材用错了可能让整个项目在上线前返工。所以每一类下面都标注了许可证性质，结尾单独说明几类常见许可的差别。

一、测试模型与规格验证

这一类资源的作用不是「好看」，而是「可诊断」。

glTF-Sample-Assets

KhronosGroup/glTF-Sample-Assets 是 glTF 2.0 官方示例模型合集，按 Showcase、Testing、Core Only 等标签分组，覆盖 PBR 材质、动画、蒙皮、形变、稀疏 Accessor 等各类特性。自带在线预览站（github.khronos.org/glTF-Assets/）。

它的正确用法不是当美术资源，而是当验收用例：自己写的导入器或者渲染器，拿 Testing 组跑一遍，哪一项崩了就是哪一处实现有问题。这比拿一个真实项目资产去调快得多——真实资产出问题时，你分不清是自己解析错了还是资产本身就不规范。

glTF-Asset-Generator

KhronosGroup/glTF-Asset-Generator 是生成上面那类测试资产的工具（C#），可以对 Accessor、Animation、Material、Mesh、Node 等特性做正例与负例生成。做导入兼容性测试时，正例验证「能读对」，负例验证「能优雅地报错」，后者往往更缺。

开源的 3D 资产集

ToxSam/open-source-3D-assets 收录近千个 CC0 的 GLB 模型（中世纪道具、室内场景、神庙等），可商用。用途是「批量压测」：一次导入几百个风格不一的真实资产，比手工造十个测试模型更容易暴露鲁棒性问题。

二、纹理压缩与格式转换

贴图的内存和带宽通常是移动端与主机上的第一瓶颈，而这类工具很少有人系统整理。

GPUOpen-Tools/compressonator 是 AMD 官方的纹理与 3D 模型压缩套件，支持 BC1–BC7、ASTC、ETC2 等格式，能直接对比不同格式下的画质（PSNR/SSIM）与体积。它的实际价值在于：决定一张贴图该用哪个格式、多少分辨率，应该靠对比图而不是靠经验。法线贴图用 BC5、带 Alpha 的 UI 用 BC7、移动端用 ASTC 4x4 或 6x6，这些结论在不同内容上的权衡并不一样。

同一批工具链里还有 BinomialLLC/basis_universal（Basis Universal），它把贴图转成可在运行时转码的中间格式（KTX2 + Basis），一份资源能同时服务桌面和移动端。需要「一套资产多端复用」时基本绕不开它。

三、PBR 贴图与材质库

Poly Haven 与批量下载

agmmnn/polydown 是 Poly Haven 的批量下载器，可以一次拉取 HDRI、PBR 贴图和 3D 模型。Poly Haven 本身是全 CC0 资源站，不要求署名、可商用，是项目里最省心的素材来源。

批量下载的意义不只是省时间：做材质分层、程序化混合或者 ML 训练集时，需要的是几十上百张同类贴图，手工点下载不现实。

物理参数

AntonPalmqvist/physically-based-api 收录金属、布料、塑料等材质的真实反射率、IOR 等数值。它的用途是给材质参数找一个物理锚点——新材质的 BaseColor 从实测数据附近开始调，比从灰白色一路试错快得多，也更不容易在同场景里出现「两件同类材质差别巨大」的问题。

跨工具材质交换

AcademySoftwareFoundation/MaterialX 与 AcademySoftwareFoundation/OpenPBR 不是素材库，而是材质在工具之间传递的标准。凡是项目里同时用 Substance、Houdini、Maya 和引擎的，材质一致性最终都要落到这两个规范上。

JackLuguibin/GameAssets 是一份游戏资产来源索引（角色、环境、PBR 贴图、UI、音频、VFX），每个条目附许可证说明。它更像目录而非素材本体，适合在「需要某类资产但不知道去哪找」时先扫一眼。

四、HDRI 与环境贴图

IBL（Image-Based Lighting，基于图像的光照）是所有 PBR 渲染的底层输入，环境贴图的处理比它看起来要麻烦。

pmndrs/env 是浏览器端的 HDR 环境贴图创建、编辑与预览工具，适合快速检查一张 HDRI 的亮度范围是否合理、有没有过曝区域。

colour-science/colour-hdri 是 Python 的 HDRI/Radiance 图像处理库，做批量处理、色彩空间校正、多张曝光合成时用它比手工操作可靠。

ProGamerGov/pytorch360convert 做等距柱状（Equirectangular）、Cubemap、透视投影之间的互转。这三者之间的转换在每个引擎里都有「内置」版本，但内置实现的采样质量和边界处理各不相同，需要精确控制时用独立工具更可控。

五、Shader 与渲染参考实现

这类项目前面学习资源里已经覆盖了一部分，这里只补充「拿来当参考实现」用得上的几个：

  • ssloy/tinyrenderer：光栅化管线的标准参考，理解每一步在做什么。
  • bkaradzic/bgfx：需要写跨后端工具时直接用它当渲染层，省掉每个 API 一遍的工作。
  • gdquest-demos/godot-shaders：现成的 Shader 实现集合，光照模型和特效思路可以移植到任何引擎。
  • QianMo/PBR-White-Paper 与 kanition/pbrtbook：理论落不到地时回去查公式出处的地方。

六、Blender 与 DCC 工作流插件

TA 的工具链工作很大一部分花在 DCC 与引擎之间，这一节是「减少重复劳动」类工具。

agmmnn/awesome-blender 是 Blender 插件、工具、教程与 3D 资源的精选列表，是找 Blender 插件的第一个入口。

具体到流程环节：

插件 作用
HurtzDonutStudios/ai-forge-mcp 面向 Blender/Substance/Maya/Houdini/UE5 的 MCP 服务器集合，把 AI 工具接进 DCC 流程
ScarlettStudios/PlaneToPBR 从单张图片生成 Diffuse/Normal/Roughness/Depth 的完整 PBR 材质
TehMerow/PBR_Bake_Tools Blender 的 PBR 材质烘焙辅助
BattlezoneScrapField/Substance-3D-Painter-Export-Presets Substance 3D Painter 的导出预设，统一输出命名与通道打包
johanhelsing/StealWithAttribution 从 HDRI Haven、Sketchfab 等站下载并自动附加署名信息

StealWithAttribution 这类工具值得留意：它把「署名」这一步自动化了。CC-BY 类素材的合规成本全在「别忘了记来源」，靠人记一定会漏。

七、通用游戏资产合集

HotpotDesign/Game-Assets-And-Resources 汇总 2D/3D、移动端与 Steam 项目的免费和付费资产来源。felladrin/game-development-resources-list 是持续更新的动态列表。

KayKit 系列提供低多边形风格资产（冒险角色包、城市建造包），适配 Unity/Godot/Unreal，适合做原型和内部 Demo——原型的价值是快速验证玩法，美术精度不重要，但要能直接导入引擎。

lexlex47/game-art-prompt-kit 是游戏美术方向的 AI 提示词模板库（像素画、概念设计、2D 环境），ComfyUI 与 Stable Diffusion 可用。生成式工具在概念阶段用来出方案草图很有效，但要注意训练数据的来源和商用条款，不要直接把生成结果当正式资产用。

八、引擎与渲染参考项目

BoomingTech/Piccolo 是 GAMES104 配套的迷你引擎，用来学引擎架构的分层方式。Angelo1211/HybridRenderingEngine 实现 Clustered Forward/Deferred 混合渲染，含 PBR、IBL 与 Compute Shader。Nadrin/PBR 把同一套 PBR + IBL 分别实现在四个图形 API 上，对拍后端差异很方便。

九、外部资源站

站点 内容 许可证
Poly Haven HDRI、PBR 纹理、3D 模型 CC0
Kenney 低多边形资产（自然、太空、城堡等） CC0
Smithsonian 3D 博物馆开放 3D 扫描模型 开放获取
Sketchfab 海量 3D 模型，支持 glTF 下载 各条目不同，需逐项确认
Poimandres Market 可下载的 glTF 格式资产 各条目不同
Cesium Demo Models 地理类 glTF 模型 Apache 2.0

许可证别混用

三类常见许可的实际差别：

  • CC0：放弃全部权利，可商用、可修改、不要求署名。项目里最省心，Poly Haven 与 Kenney 都是这一类。
  • CC-BY：可商用，但必须署名，且署名信息要能随资产一起走到最终产品里。麻烦点在于「怎么让美术同事在管线里顺手保留署名」。
  • 带 NC（NonCommercial）或 SA（ShareAlike）的变体：商用受限，或者要求衍生作品使用同样许可。这两类在商业项目里基本要避开。

Sketchfab 与 Poimandres Market 是聚合平台，许可证逐条不同，需要按条目确认。上线前做一次资产清单核对，比事后返工便宜得多。

十、优先收藏

如果只留几个入口，优先这几个：

  1. glTF-Sample-Assets — 做渲染器和导入器时的验收用例，测试组比任何真实资产都好用。
  2. awesome-blender — Blender 相关工具的一站式入口。
  3. physically-based-api — 调材质时查物理参数，比凭感觉试快得多。
  4. polydown — Poly Haven 批量下载，CC0 且可商用。
  5. MaterialX — 跨 DCC 材质交换的事实标准。
  6. compressonator — 贴图格式与压缩质量的对比依据。

总结

素材类资源的挑选标准和学习类资源不一样，它更看三件事：

能不能诊断问题。 测试模型、格式对比工具、参数库都属于这一类。它们的共同点是让你在出问题时能定位到具体环节，而不是只能靠试。

许可证清不清。 CC0 与 CC-BY 的差别不是「要不要写个链接」这么简单，它决定资产能不能进最终包体。项目早期就把来源和许可证记下来，成本几乎为零；等上线前再回溯，往往已经找不到出处。

能不能自动化。 批量下载、批量转换、自动附加署名，这些工具的价值在于把一次性劳动变成可重复执行的流程。TA 的工作本质上是把重复劳动做成工具，素材管理也不例外。
