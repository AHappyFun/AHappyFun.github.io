Base-引擎梳理

#原理

本文在原有“引擎知识地图”的基础上补充概念说明与延伸资料。星级沿用原有标记，从基础知识（⭐）到前沿或引擎级内容（⭐⭐⭐⭐），用于表示建议的学习顺序，而非技术价值的高低。

通用参考（贯穿全文，各节不再重复）

  • Journal of Computer Graphics Techniques (JCGT) — 开源期刊，论文基本都带源码
  • GDC Vault — GDC 演讲录像/幻灯片
  • Ray Tracing Gems I / II（免费书） — 光追综合参考
  • PBRT（离线渲染圣经，免费 PDF） — 理解光传输、加速结构、渲染方程
  • Scratchapixel — 图形学系统教程
  • LearnOpenGL — 图形 API 实践入门
  • Vulkan Tutorial — Vulkan 手把手

一、渲染管线架构（Engine Rendering Architecture）

⭐⭐⭐（非常重要）

现代引擎不再是一条”固定流水线”，而是把渲染组织成 “资源 + Pass + 依赖” 的图结构，让引擎自动管理内存、同步与调度。这一节是整个渲染系统的骨架，先看 ① 和 ③ 打底，再啃 ② 和 ④。

这些是现代引擎渲染系统的骨架。

Frame Graph / Render Graph

把一帧渲染建模成一张有向无环图（DAG）——节点是 Render Pass，边是 Pass 之间读写的资源。引擎据此自动计算资源生命周期、复用 Transient RT（同一内存块供不同 Pass 轮流使用）、自动插入 Barrier/同步，甚至能在运行时重排 Pass。代表实现：Frostbite FrameGraph、The Forge、Unity 6 Render Graph、UE 的 RDG。

拓展资料

  • FrameGraph: Extensible Rendering Architecture in Frostbite（GDC 2017，Yuriy O’Donnell） — 这个概念的开山之作，必看
  • Frostbite 官方博客（同题）
  • The Forge 渲染框架（开源，含 RenderGraph）
  • Unity Render Graph 文档

GPU Driven Rendering

把整个场景（网格、材质、矩阵、包围盒）塞进 GPU Buffer，剔除、排序、间接绘制全在 GPU 上完成，CPU 只提交少量间接命令，消除 draw call 与 CPU-GPU 同步瓶颈。它是 Nanite、Mesh Shader、DOOM 这类”下一代表现”的共同底座。

拓展资料

  • Block-Based GPU-Driven Rendering（GDC 2018，Sebastian Aaltonen） — 作者主页，找 “Block-Based GPU-Driven Rendering” 演讲
  • SIGGRAPH 2020 DOOM Eternal 渲染课程（GPU 驱动/阴影/体素化）
  • nvpro-samples（NVIDIA 官方 Vulkan 示例集，含 GPU-Driven 示例）

Command Buffer / Render Queue

CPU 把绘制工作录进 Command Buffer，提交给 GPU 的不同队列（Graphics / Compute / Copy）异步执行。多队列可并行（→ Async Compute），多线程录制 Command Buffer 是现代 API（D3D12/Vulkan）下提升 CPU 性能的核心手段。

拓展资料

  • Vulkan Tutorial — Command Buffers — 把流程走一遍
  • D3D12 官方文档（Command Lists & Queues）
  • Getting Started with Direct3D 12（示例代码）

Resource Management

GPU 内存管理四件套：Render Target Pool 复用中间渲染目标；Transient Resource 只在单帧内有效、与其他资源共享显存；Texture Streaming 按需加载 mip/图块；Virtual Texture 把超大纹理切成 Page 按需上传 + 缓存淘汰，支持”无限大”纹理。

拓展资料

  • D3D12 内存管理 / 同步文档
  • Vulkan Memory Allocator（VMA，社区标准内存池实现）
  • UE 虚拟纹理（Virtual Texture）文档
  • 配合第一节 FrameGraph 的 Transient 资源看效果最佳

二、几何与可见性（Geometry & Visibility）

⭐⭐ ～ ⭐⭐⭐

可见性决定了”每帧往 GPU 喂多少三角形”。方向是：从 CPU 粗粒度剔除（Frustum）→ 细粒度遮挡剔除（HZB/Occlusion）→ 完全交给 GPU（Cluster/Meshlet/GPU-Driven）。

基础

Frustum Culling ⭐

视锥剔除。用视锥的 6 个平面与物体包围盒/包围球做相交测试，直接扔掉完全在视锥外的物体。最古老、最省钱的粗粒度剔除，CPU 或 GPU Compute 都能做。

拓展资料

  • Real-Time Rendering 4e — 第 19 章（几何检测）
  • Gribb & Hartmann, Fast Extraction of Viewing Frustum Planes（经典论文，搜索即得）

Occlusion Culling ⭐⭐

遮挡剔除。物体没被视锥剔除，但被墙挡死了——测试它是否被已渲染的东西遮住，从而跳过。常见手段：上一帧深度回读、Hierarchical-Z 查询、或 GPU 驱动的 compute 剔除。

拓展资料

  • DOOM 2016 Graphics Study（Adrian Courrèges，含剔除思路）
  • GDC 2019 Optimizing the Graphics Pipeline with Compute（UBI，含 HZB 遮挡剔除）
  • nvpro-samples（GPU-Driven 示例含遮挡剔除）

Hi-Z Buffer ⭐⭐

分层深度缓冲（Hierarchical-Z）。把深度图降采样成金字塔，用每层”最浅深度”做保守的快速遮挡测试（2x2/4x4 块级），同时是屏幕空间圆锥追踪、SSR、剔除的共同基础设施。

拓展资料

  • Screen Space Ray Tracing（McGuire & Mara 博客，讲 Hi-Z 追踪原理）
  • GDC 2019 Optimizing the Graphics Pipeline with Compute（HZB 剔除实作）

现代 GPU 可见性

Cluster Culling ⭐⭐⭐

把网格切成一堆小簇（Cluster，几十~几百个三角形），逐簇做剔除与 LOD，粒度比逐物体细得多，且天然适合 GPU 并行与 Mesh Shader。

拓展资料

  • Sebastian Aaltonen（Cluster-Based Rendering / Block-Based GPU-Driven）
  • Nanite: A Deep Dive（SIGGRAPH 2021）

Meshlet Rendering ⭐⭐⭐

把网格切成 Meshlet（64~128 个三角形的小块），由 Task + Mesh Shader 逐 Meshlet 剔除并直接生成绘制命令，实现”每小块级”的 LOD 与剔除。DX12 Mesh Shader / Vulkan VK_EXT_mesh_shader。

拓展资料

  • DirectX-Specs — Mesh Shader 规范
  • NVIDIA — Introduction to Turing Mesh Shaders（GDC 2019）
  • Nanite: A Deep Dive（SIGGRAPH 2021）

GPU Driven Pipeline ⭐⭐⭐

可见性判断也在 GPU 上完成——GPU 算完”哪些可见”后直接写出 Indirect Draw 命令，CPU 完全不参与剔除。见第一节 GPU Driven Rendering。

拓展资料

  • 同第一节 GPU Driven Rendering 的所有链接

空间结构

BVH ⭐⭐⭐

包围体层次结构。用一棵”包围盒嵌套包围盒”的树做加速遍历，是**现代光追加速结构（RTX 底层）**和多数物理引擎的基石，可用 SAH 优化构建质量。

拓展资料

  • PBRT — BVH 章节
  • Ray Tracing in One Weekend（动手写一个 BVH）
  • D3D12 Raytracing — Acceleration Structures

Octree ⭐⭐

八叉树。空间均匀八分，天然支持多分辨率（LOD），适合稀疏场景、体素、碰撞与空间划分。

拓展资料

  • Octree-Based Sparse Voxelization（OpenGL Insights 第 22 章，Crassin & Green）
  • OpenGL Insights 全书（免费 PDF，Apress）

KD Tree ⭐⭐

KD 树。按维度交替切分空间，静态场景下光追效率常优于 BVH，但构建慢、难做动态，多见于离线渲染。

拓展资料

  • PBRT — 加速结构章节
  • Wald & Havran, On Building Fast kd-Trees for Ray Tracing（经典论文）

高级

Nanite-like virtual geometry ⭐⭐⭐⭐

UE5 Nanite 的”虚拟几何”范式：任意精度的模型数据以簇/DAG 形式驻留 GPU，运行时做逐像素/逐簇 LOD + 剔除，用 Compute 直接输出微三角形，彻底绕开传统 LOD 美术管线。自己实现相当于”再造半个渲染器”。

拓展资料

  • Nanite: A Deep Dive（SIGGRAPH 2021，Karis 等）
  • UE5 Nanite 官方文档
  • GDC 2023 A Deep Dive into Nanite Virtualized Geometry

三、光照系统（Lighting）

⭐⭐ ～ ⭐⭐⭐

光照分两条线：着色架构（光从哪来、怎么累积）与阴影（光被什么挡住）。

传统

Forward Rendering ⭐

前向渲染。每个物体对”影响它的所有光源”依次叠加着色，简单直观、支持 MSAA、透明物体好处理；但光源一多开销直线上升。

拓展资料

  • LearnOpenGL — 光照系列（前向渲染就是其默认方式）
  • Filament 文档（Google，Forward 着色讲解）

Deferred Rendering ⭐

延迟渲染。第一遍把几何信息（位置/法线/材质/颜色）写进 G-Buffer，第二遍只对屏幕像素做光照，把光照复杂度与场景复杂度解耦，支持海量光源；代价是带宽大、MSAA 困难、透明物体要另走一遍。

拓展资料

  • LearnOpenGL — Deferred Shading
  • Real-Time Rendering 4e — 第 20 章（光照与阴影）

Tiled Lighting ⭐⭐

把屏幕切成 2D 瓦片（Tile），每个 Tile 收集影响它的光源列表（Light List），着色时只遍历本 Tile 的光源，省掉全局光源循环。

拓展资料

  • Aaltonen — Practical Clustered Shading（GDC 2015，Tiled 的升级版）
  • DOOM 2016 Graphics Study（实际用了 Clustered 光源索引）

Clustered Lighting ⭐⭐

聚类光照（Clustered / Forward+）。把视锥体切成三维格簇，每簇记录光源索引，Forward 和 Deferred 都能用，彻底解决”动态光源数量上限”。

拓展资料

  • Aaltonen — Practical Clustered Shading（GDC 2015）
  • Olsson et al., Clustered Deferred and Forward Shading（2012，搜索即得）

阴影

Shadow Map ⭐

阴影贴图。从光源渲染一遍深度，着色时比较”自己到光源的距离 vs 贴图里的深度”判断遮挡。所有阴影变体的地基。

拓展资料

  • LearnOpenGL — Shadow Mapping

Cascaded Shadow Map ⭐⭐

级联阴影（CSM）。把视锥按距离切成几级，每级一张 Shadow Map——近处高精度、远处大覆盖，是方向光阴影的事实标准。

拓展资料

  • UE 级联阴影映射文档
  • Parallel-Split Shadow Maps（Zhang et al.，CSM 的理论基础，搜索即得）

Variance Shadow Map ⭐⭐

方差阴影贴图（VSM）。存深度”均值 + 方差”，用概率估计遮挡，可配合滤波直接做软阴影；代价是 light bleeding（漏光）。

拓展资料

  • GPU Gems 3 — Chapter 8: Summed-Area Variance Shadow Maps
  • Donnelly & Lauritzen, Variance Shadow Maps（2006）

Moment Shadow Map ⭐⭐

矩阴影贴图（MSM）。用深度的 4 阶矩重建遮挡分布，滤波软阴影的质量远高于 VSM、漏光大幅减少，用 64bit/纹素即可。

拓展资料

  • Moment Shadow Mapping（i3D 2015，Peters & Klein，ACM DL）
  • 作者主页 momentsingraphics.de（含后续 MSM 系列）

Distance Field Shadow ⭐⭐⭐

SDF 阴影。用场景的有符号距离场做 Sphere Tracing，直接得到精确、柔和、带接触感的阴影。UE4/5 的 Distance Field Shadow 就是它。

拓展资料

  • Iñigo Quilez — Soft Shadows in Ray-marched SDFs
  • UE 距离场文档
  • Keinert et al., Enhanced Sphere Tracing（2014）

Ray traced shadow ⭐⭐⭐

光追阴影。沿光源方向打一条 Shadow Ray，得到精确的软硬阴影、接触阴影、透明物体色影，配合降噪实时运行（DXR / Vulkan RT / OptiX）。

拓展资料

  • Ray Tracing Gems（免费书，阴影章节）
  • Ray Tracing in One Weekend
  • D3D12 Raytracing 文档

四、GI（Global Illumination）

⭐⭐ ～ ⭐⭐⭐⭐

GI = 间接光。从”烘焙静态”到”全动态实时”，是画面上限与引擎技术含量的分水岭。

传统

Lightmap ⭐

光照贴图。把离线烘焙的间接光写进 UV 纹理，运行时采样。质量高、开销低，但静态、占内存、依赖 UV。

拓展资料

  • Unity Lightmap 文档
  • UE 光照烘焙（Lightmass / Lumen 混合）文档

SH Probe ⭐

球谐光照探针。在场景布点，记录入射辐照度的球谐系数，运行时插值给漫反射间接光——离线 GI 里动态物体接光的标准答案。

拓展资料

  • Peter-Pike Sloan — Stupid SH Tricks（球谐权威）
  • Unity Light Probes 文档

Light Probe Proxy Volume ⭐⭐

LPPV。把探针体积细分，让动态物体在做探针插值时更精确，改善”动态角色在渐变光环境里接光不连续”的问题。

拓展资料

  • Unity Light Probe Proxy Volume 文档

实时 GI

Screen Space GI ⭐⭐

屏幕空间 GI（SSGI）。用屏幕深度/法线做光线步进，把间接光反射到邻近像素。好实现、效果好，但只认屏幕内信息，会漏光、有屏幕边缘伪影。

拓展资料

  • Real-Time Global Illumination（SIGGRAPH 2009 课程，含 SS 技术族谱）
  • Screen Space Indirect Lighting with Visibility Bitmask（arXiv 2301.11376，新一代 SSGI）

DDGI ⭐⭐⭐

动态漫反射 GI。用光追把辐照度写进 3D 体积探针纹理，逐帧动态更新，支持动态场景的实时间接漫反射光，漏光用 Chebyshev 可见性权重压制。NVIDIA RTXGI 的 DDGI 就是它。

拓展资料

  • Dynamic Diffuse GI with Ray-Traced Irradiance Fields（JCGT 2019，Majercik 等）
  • RTXGI-DDGI 开源实现（NVIDIA）
  • RTXGI 官方页

SDF GI ⭐⭐⭐

基于距离场的 GI。用全局距离场做 Ray March 估算间接光遮挡与反弹。UE 的 Distance Field GI（配合降噪）就是它，支持动态几何、粗糙的多次反弹。

拓展资料

  • UE 距离场 GI 文档
  • SIGGRAPH 2020 DOOM Eternal 课程（含 SDF 相关实现）

Voxel GI ⭐⭐⭐

体素 GI。把场景体素化（3D 纹理 / SVO），在体素空间做锥追踪或光追。代表：Voxel Cone Tracing（Crassin）、CryEngine 的 SVOGI。

拓展资料

  • Interactive Indirect Illumination Using Voxel Cone Tracing（Crassin 等，EUROGRAPHICS 2011）
  • GigaVoxels（Crassin，稀疏体素渲染）

ReSTIR GI ⭐⭐⭐⭐

时空重采样 GI。用 Reservoir 采样 + 空间/时间复用，把每像素的光路开销压到几条内，配合降噪逼近路径追踪级的实时间接光。当前实时 GI 最前沿。

拓展资料

  • Spatiotemporal Reservoir Resampling（SIGGRAPH 2020，Bitterli 等）
  • ReSTIR GI（Wyman & Panteleev，HPG 2021）— SIGGRAPH 2021 课程里有解读

Lumen-like GI ⭐⭐⭐⭐

UE5 Lumen 的”全动态 GI”范式：SDF 追踪 + 屏幕追踪 + Surface Cache + 降噪，不用烘焙，支持动态场景与多次反弹。要做出类似效果需要自己拼装整条管线。

拓展资料

  • UE5 Lumen 官方文档
  • SIGGRAPH 2022 课程（含 Lumen 实现细节）

五、Screen Space 技术

⭐⭐

屏幕空间（SS）技术只消费”当前画面已有的信息”（深度/法线/颜色），成本低、易集成，是性价比最高的画质加成；代价是看不到屏幕外。

SSAO ⭐⭐

屏幕空间环境光遮蔽。以深度/法线在像素周围半球采样，估计”缝隙、墙角”这类接触细节造成的暗角。Crytek 2007 提出，从此 AO 进入屏幕空间时代。

拓展资料

  • LearnOpenGL — SSAO
  • Mittring, Finding Next Gen: CryEngine 2（SSAO 出处，2007）

HBAO ⭐⭐

水平线 AO。把半球采样改成”沿方向扫描找最高水平线（Horizon Angle）”+ 解析积分，比 SSAO 稳定、噪点更少。NVIDIA 在 2008 提出，HBAO+ 是其进化版。

拓展资料

  • Image-Space Horizon-Based Ambient Occlusion（SIGGRAPH 2008，ACM DL）
  • HBAO+ 开源实现

GTAO ⭐⭐⭐

Ground Truth AO。在 HBAO 基础上做多方向采样 + 解析 cos 加权积分 + 时间滤波，得到接近物理真实的 AO，且支持间接光照估计。UE4/5、大量引擎的默认 AO 就是它。

拓展资料

  • Practical Real-Time Strategies for Accurate Indirect Occlusion（Jimenez 等，Activision，SIGGRAPH 2016）

SSR ⭐⭐

屏幕空间反射。沿反射方向在深度缓冲里 Ray March，找命中点得到屏幕内反射。便宜，但只反射”屏幕里能看到的东西”，边缘会漏。进阶用”随机 + 时域复用”降噪。

拓展资料

  • Screen Space Ray Tracing（McGuire & Mara 博客）
  • Stochastic Screen-Space Reflections（Frostbite 版幻灯片）

SSGI ⭐⭐

屏幕空间 GI。见第四节 Screen Space GI。

拓展资料

  • 同第四节 Screen Space GI 的链接

Contact Shadow ⭐⭐

接触阴影。沿表面做短距离屏幕空间锥/光线步进，补出 Shadow Map 精度够不到的”脚边、缝隙”阴影，画面立刻”接地气”。

拓展资料

  • UE Contact Shadows 文档
  • SIGGRAPH 2020 DOOM Eternal 课程（含接触阴影实现）

六、Temporal 技术

⭐⭐⭐

时间维复用（用上一帧的信息换本帧的质量）是近十年画质跃升的最大杠杆：TAA / 超分 / 降噪都靠它。

TAA ⭐⭐⭐

时域抗锯齿。每帧对采样点做 Jitter，把上一帧结果按 Motion Vector 重投影后与当前帧混合，大幅消灭锯齿与闪烁；代价是重影（Ghosting）和轻微柔化。

拓展资料

  • High Quality Temporal Supersampling（Karis，SIGGRAPH 2014）
  • Temporal Reprojection Anti-Aliasing in INSIDE（Playdead，SIGGRAPH 2016 课程）

TAAU ⭐⭐⭐

时域超采样（Temporal Anti-Aliasing Upsampling）。在 TAA 框架里用重建 + 锐化输出比渲染分辨率更高的画面，是 UE4/5 TAAU、DLSS/FSR 的概念祖先。

拓展资料

  • 同上 Karis 2014（TAAU 的源头）
  • UE TAAU 相关文档

TSR ⭐⭐⭐

UE5 的时域超分辨率（Temporal Super Resolution）。用 Motion Vector + 历史累积 + 空间重建把低分辨率画面超分到目标分辨率，不依赖特定硬件，质量接近 DLSS/FSR。

拓展资料

  • UE5 TSR 官方文档

DLSS integration ⭐⭐

NVIDIA 深度学习超采样。用 Tensor Core 跑神经网络，从”低分辨率 + 运动矢量”重建高分辨率画面（DLSS 2/3 还有帧生成）。需要 SDK + 特定硬件。

拓展资料

  • NVIDIA DLSS 官方页

FSR integration ⭐⭐

AMD FSR。开放源码的超分方案（FSR1 是空间算法，FSR2/3 是时域 + 帧生成），不依赖特定硬件，易集成。

拓展资料

  • AMD FidelityFX Super Resolution 官网
  • FidelityFX-FSR2 源码（GitHub）

Motion Vector ⭐⭐⭐

运动矢量。每像素记录”本帧→上一帧”的位移（相机运动 + 物体运动），是 TAA、超分、运动模糊、光追降噪共同依赖的输入。

拓展资料

  • UE Motion Blur 文档（运动矢量怎么用）
  • 与 TAA 同一批课程（Karis 2014）

History rejection ⭐⭐⭐

历史拒绝。当历史数据不可信（被遮挡、光线突变、新物体出现）时，用邻域比较/深度法线检查丢弃或减弱历史采样，避免 Ghosting 与画面滞后。TAA、超分、降噪里最关键也最容易翻车的一环。

拓展资料

  • Karis 2014（TAA 的 Ghosting 处理）
  • Ray Tracing Gems（含光追降噪的历史复用章节）

七、体积渲染（Volumetric）

⭐⭐ ～ ⭐⭐⭐

处理”介质”而非”表面”：雾、烟、光束、大气。核心概念是参与介质（散射/吸收）与光线步进。

Height Fog ⭐

高度雾。按”世界高度 + 相机距离”做指数衰减叠雾色，能做出”山谷雾、山脚雾气”这种随高度变化的雾。UE 的 Exponential Height Fog 就是它。

拓展资料

  • UE Exponential Height Fog 文档

Volumetric Fog ⭐⭐

体积雾。把雾体采样到 3D 体积纹理里逐帧更新，配合光照做 Ray March 合成，得到有层次的体积光与雾。UE4 的 Volumetric Fog、Remedy 的 Nubis 都是这套思路。

拓展资料

  • UE Volumetric Fog 文档
  • DOOM 2016 Graphics Study（含体积雾实作）
  • Remedy, The Nubis System（Control 的体积雾，搜索即得）

Participating Media ⭐⭐⭐

参与介质。物理地模拟光在介质中的吸收、散射、各向异性（Henyey-Greenstein 相位函数），是体积雾、烟雾、大气散射的统一理论框架。

拓展资料

  • Scratchapixel — 体积渲染 / 大气散射

Volumetric Lighting ⭐⭐

体积光照。让光在雾中产生可见的体积光束（手电筒光柱、窗户漏光），本质是”雾 + 光源”在 3D 体纹理里做步进。

拓展资料

  • 同 Volumetric Fog 与 God Ray 的链接

Light Scattering ⭐⭐

光散射。光与大气/粒子作用（瑞利散射、米氏散射）产生天光、雾、光晕。广义上含完整的大气散射模型（渲染真实天空）。

拓展资料

  • A Scalable and Production Ready Sky and Atmosphere Rendering Technique（Hillaire，SIGGRAPH 2020）
  • Scratchapixel — 大气散射

God Ray ⭐⭐

上帝光 / 体积光柱。光被介质散射形成的可见光柱，经典做法是后处理里”沿光源方向径向模糊”（Killzone 2 的方案），低成本又好看。

拓展资料

  • GPU Gems 3 — Chapter 13: Volumetric Light Scattering as a Post-Process

八、距离场 / 体素系统

⭐⭐⭐

你刚开始做 SDF，这块是引擎级技术。核心思路：把”连续三角形几何”转成”可随时查询的场”，换取光照/阴影/碰撞的稳定与柔和。

你刚开始做 SDF，这块是引擎级技术。

Mesh Distance Field

网格距离场。把单个静态网格转换成有符号距离场（SDF），可查”任意点到表面的距离与方向”，用于阴影、AO、GI、碰撞近似、寻路。UE 的 Mesh Distance Field 即此。

拓展资料

  • UE 距离场文档
  • Iñigo Quilez — SDF 入门与图元库

Global Distance Field

全局距离场。把整个场景的 SDF 合并成一个全局场（分层 Clipmap 结构），支持任意位置的全局 SDF 查询——GI、阴影、AO 的公共数据源。

拓展资料

  • UE Global Distance Field 文档

SDF AO

距离场环境光遮蔽。沿法线在 SDF 里步进，估算”几何多近”得到接触/局部 AO——比屏幕空间 AO 稳定得多，不依赖屏幕内容。

拓展资料

  • Iñigo Quilez — Ambient Occlusion in Ray-marched SDFs

SDF Shadow

见第三节 Distance Field Shadow。SDF 步进天然得到精确柔和阴影。

拓展资料

  • 同第三节 Distance Field Shadow 的链接

Voxelization

体素化。把三角形网格离散到体素栅格，用于 GI、碰撞、材质查询。主流方式：GPU 硬件光栅化（保守光栅化）、射线驱动、或纯 Compute。

拓展资料

  • Octree-Based Sparse Voxelization Using the GPU Hardware Rasterizer（OpenGL Insights）

Sparse Voxel Octree

稀疏体素八叉树（SVO）。只存”非空”体素，能承载超高分辨率的体素场景，是 GigaVoxels、Voxel Cone Tracing 乃至 Nanite 思路的前身。

拓展资料

  • GigaVoxels（Crassin 等，2009）
  • Voxel Cone Tracing（Crassin 等，2011）

九、后处理系统

⭐

3D 场景渲染完后的全屏滤镜阶段。成本低、观感提升巨大，是”画质”的最后一公里，也是屏幕空间技术的最大聚集地。

基础但必须会。

Bloom

泛光/辉光。提取高亮区域 → 多级降采样模糊 → 上采样叠加，模拟光晕。几乎所有画面”高级感”都靠它。

拓展资料

  • LearnOpenGL — Bloom

Tone Mapping

色调映射。把 HDR 场景值压缩到 LDR 显示范围，决定画面亮度、对比度、高光衰减。主流：ACES、Filmic、Reinhard。

拓展资料

  • LearnOpenGL — HDR / Tone Mapping
  • Filament 文档 — Tone Mapping

Color Grading

颜色分级。对画面做全局色彩调节（曝光、白平衡、饱和度、LUT、曲线），统一风格。3D LUT 是主流手段。

拓展资料

  • UE Color Grading 文档

Depth of Field

景深。模拟镜头焦距外的模糊，分前景/后景，圆形散景（Bokeh）是质量关键。

拓展资料

  • UE Depth of Field 文档

Motion Blur

运动模糊。沿 Motion Vector 方向模糊，增强速度感；物体级（Per-Object）比全屏模糊更自然。

拓展资料

  • UE Motion Blur 文档

Lens Flare

镜头光晕。模拟镜头内部反射的亮斑/鬼影，分”基于真实镜头数据”与”美术手K”两类。

拓展资料

  • UE Lens Flare 文档

Chromatic Aberration

色差。模拟镜头对不同波长光折射不同导致的 RGB 边缘色散，常用作沉浸感滤镜（对边缘加即可，别糊全屏）。

拓展资料

  • ShaderToy 搜索 “Chromatic Aberration”（大量实时实现）

十、抗锯齿技术

⭐⭐

对付”锯齿”的手段分两类：几何级（MSAA，只对三角形边有效）与后处理级（图像空间，管全部高频细节）。

MSAA

多重采样抗锯齿。光栅化时对每像素多个覆盖样本求平均，只平滑几何边；开销随样本数上升，Deferred 下不兼容（需要在 G-Buffer 阶段多采样）。

拓展资料

  • LearnOpenGL — MSAA

FXAA

快速近似抗锯齿。纯后处理：检测边缘 → 模糊。便宜但对亚像素/纹理细节不友好，画面偏糊，现在一般作为兜底。

拓展资料

  • FXAA White Paper（Timothy Lottes，NVIDIA 2009）

SMAA

亚像素形态学抗锯齿。边缘形态检测 + 模式识别 + 时间滤波，质量高于 FXAA、低于 TAA，移动端常用。

拓展资料

  • SMAA: Enhanced Subpixel Morphological Antialiasing（Jimenez 等，官方页）

TAA

见第六节 TSR（时域超分）。

十一、现代 GPU 技术

⭐⭐⭐

从”光栅化 + 固定管线”走向”通用并行计算”：GPU 不再是只画三角形，而是一台大规模并行机。越来越重要。

越来越重要。

Compute Shader Pipeline

计算着色器。不经过光栅化、以线程组（Threadgroup）为单位的通用并行程序，用来做剔除、降噪、后处理、模拟等一切”非三角形”工作。

拓展资料

  • Vulkan Tutorial — Compute Shaders
  • LearnOpenGL — Compute Shaders

Async Compute

异步计算。用独立 Compute Queue 让”计算类工作”与图形并行，把 GPU 空闲的执行单元利用起来。DOOM 用它压榨出大量性能；注意同步与带宽争抢。

拓展资料

  • DOOM 2016 Graphics Study（Async Compute 实战分析）
  • SIGGRAPH 2020 DOOM Eternal 课程

Wave Intrinsics

波前/子组（Wavefront/Subgroup）内建函数。让同一 Wave 内线程直接交换数据、投票、做 Scan，替代共享内存实现更高效的归约与协作算法（HLSL WaveOps / Vulkan VK_KHR_shader_subgroup）。

拓展资料

  • Khronos — Vulkan Subgroup Tutorial
  • Microsoft — HLSL Wave Intrinsics 文档

GPU Prefix Sum

并行前缀和（Scan）。Hillis-Steele / Blelloch 等高效并行算法，是排序、流压缩（Stream Compaction）、GPU 驱动的间接绘制的基础。

拓展资料

  • GPU Gems 3 — Chapter 39: Parallel Prefix Sum (Scan) with CUDA
  • NVIDIA CUB（并行原语库）

GPU Sorting

GPU 排序。用 Bitonic / 基数排序等并行算法做材质排序、透明排序、粒子排序、可见性排序。CUB / Thrust 直接可用。

拓展资料

  • NVIDIA CUB
  • NVIDIA Thrust

Indirect Dispatch

间接分发/绘制。命令参数由 GPU 自己写（Compute 输出 Draw 参数），CPU 不用回读，实现”GPU 驱动”的完整闭环。

拓展资料

  • D3D12 — ExecuteIndirect / 间接绘制
  • nvpro-samples（GPU-Driven 示例）

十二、数据压缩 / 纹理系统

⭐⭐

纹理/几何数据的存储与传输决定内存与带宽——移动端与主机优化的主战场，直接关系帧率。

Texture Compression

纹理压缩。块压缩（Block-based）：把像素块编码成固定比特率、GPU 可直接硬件采样的格式（无需解压）。质量、比特率、带宽是三角关系。

拓展资料

  • Understanding BCn Texture Compression Formats（reedbeta）
  • Basis Universal（通用纹理压缩库）

ASTC / BC

两大压缩族。BC（DXT/BC1BC7）是 DX 系；ASTC（ARM/Khronos）是移动端主流，支持 4x412x12 灵活比特率与 RGBA 各种通道组合。

拓展资料

  • Khronos ASTC 官方页
  • ARM — ASTC Texture Compression 文档

Mipmap Streaming

mip 流送。按需加载 mip 层级（先低清后高清），是 Texture Streaming 的基础，显著减少加载时间与内存。

拓展资料

  • LearnOpenGL — Mipmaps
  • UE Texture Streaming 文档

Virtual Texture

虚拟纹理。把超大纹理/地形拆成 Page，按需上传 GPU（配合 Feedback 查询），支持远超显存尺寸的纹理，配合 Clipmap 做无缝大地形。

拓展资料

  • UE 虚拟纹理文档
  • SIGGRAPH 2015 Advanced Virtual Texture Topics（The Witness 等厂商分享）

Clipmap

Clipmap。以相机为中心的多级”网格/纹理”叠层，每级更大范围、更粗分辨率，用于地形、海面、全局距离场等”无限大”场景。

拓展资料

  • GPU Gems 2 — Chapter 2: Terrain Rendering Using GPU-Based Geometry Clipmaps
  • Geometry Clipmaps（Hoppe 原始论文页）

十三、粒子系统 / GPU 特效

⭐⭐

GPU Simulation

  • Position Based Fluids（同上）

Fluid Sim

流体模拟。网格法（Euler，3D 纹理 + 迭代求解）或粒子法（SPH/PBF）模拟流体运动；GPU 上跑速度与分辨率是关键。

拓展资料

  • GPU Gems 1 — Chapter 38: Fast Fluid Dynamics Simulation on the GPU
  • Jos Stam, Real-Time Fluid Dynamics for Games（经典，搜索即得）

Niagara-like systems

UE5 Niagara 式的下一代粒子/特效系统：节点化图 + GPU/CPU 混合模拟 + 深度接入渲染管线（事件、调试、数据接口）。

拓展资料

  • UE Niagara 官方文档
  • Unity Visual Effect Graph（对标方案）

十四、引擎级优化

⭐⭐⭐

真正的工程能力：把”能跑”变成”稳定、流畅、不烫手地跑”。这一节是性能分析 + 数据结构 + 内存设计的综合。

真正的工程能力。

Frame Pacing

帧节奏。保证每帧耗时均匀（不忽快忽慢），手段：固定步长、垂直同步策略、GPU 绑定（Bounded）渲染、输入延迟控制。节奏乱比帧率低更难受。

拓展资料

  • Vulkan Tutorial — Swapchain / Frames in Flight（帧节奏的工程基础）
  • John Carmack, Latency Mitigation Strategies（GDC 2015，输入延迟方向）

GPU/CPU sync

CPU/GPU 同步。CPU 不能无限领先 GPU（命令队列有界），通过 Fence/Semaphore 同步；代价是等待（Bubble），用多缓冲（Double/Triple Buffering）化解。

拓展资料

  • Vulkan Tutorial — Synchronization
  • D3D12 — Fences

Cache friendly layout

缓存友好布局。数据按访问模式排布（SoA/AoS、内存池、多线程分区），减少 Cache Miss 与线程冲突。配合数据导向设计（DOD）/ ECS。

拓展资料

  • Game Programming Patterns — Data Locality
  • Data-Oriented Design 书籍官网
  • Mike Acton, Data-Oriented Design and C++（CPPCon 演讲，搜索即得）

Bandwidth optimization

带宽优化。显存带宽是移动/主机的硬瓶颈，通过压缩、减少读写往返、复用 L2/共享内存、合并访问来省带宽——常常比省运算更有效。

拓展资料

  • A Trip Through the Graphics Pipeline（Fabian Giesen，讲 GPU 带宽/延迟）
  • ARM — Understanding GPU Bandwidth

Memory pool

内存池。预分配大块内存按需切分，避免频繁 malloc/free 与碎片化；GPU 侧用内存分配器（VMA、D3D12 Heap）减少驱动开销。

拓展资料

  • Vulkan Memory Allocator
  • Game Programming Patterns — Object Pool

GPU profiler

GPU 性能分析器。定位 GPU 瓶颈（占用率、带宽、Pass 耗时）。常用：Nsight Graphics、PIX、RenderDoc、AMD RGP。会看分析器是工程能力的硬指标。

拓展资料

  • RenderDoc（开源的”抓帧神器”）
  • NVIDIA Nsight Graphics 文档
  • PIX（微软 D3D 调试/分析）
  • AMD Radeon GPU Profiler

十五、现代引擎的新趋势

⭐⭐⭐⭐

未来几年会越来越重要：GPU 更自主（Work Graphs）、几何处理范式变革（Mesh Shader）、场景从”资产”走向”程序化生成”，以及 AI 进入渲染。

未来几年会越来越重要。

Work Graphs（DX12）

DX12 工作图。GPU 端动态生成与调度工作（节点图），无需 CPU 介入即可递归产生后续工作，是”GPU 自治”的下一步，目标替代部分 Indirect/Async 编排。

拓展资料

  • DirectX-Specs — Work Graphs 规范
  • NVIDIA — Work Graphs 技术博客

Mesh Shader pipeline

网格着色器管线。用 Task + Mesh Shader 取代传统 VS/GS/Primitive 阶段，几何由 GPU 灵活生成与剔除——GPU 驱动几何与 Nanite 类方案的基石。

拓展资料

  • DirectX-Specs — Mesh Shader 规范
  • NVIDIA — Introduction to Turing Mesh Shaders
  • AMD — RDNA Mesh Shaders（GPUOpen）

GPU Driven Rendering

作为趋势再强调：整个场景管理与可见性在 GPU 闭环，CPU 只当”搬运工”。

拓展资料

  • 同第一节 GPU Driven Rendering 的链接

Procedural world streaming

程序化世界流送。地形/植被/建筑按需程序化生成 + 分块流送，让”无限大世界”可跑（UE World Partition、Houdini + 引擎管线）。

拓展资料

  • UE World Partition 文档
  • Houdini（程序化内容生成工具）

Neural rendering

神经渲染。用神经网络替换/增强渲染环节：超分（DLSS）、新视角合成（NeRF、3D Gaussian Splatting）、材质/光照学习。渲染与 AI 的交汇前沿。

拓展资料

  • NeRF: Representing Scenes as Neural Radiance Fields（arXiv 2003.08934）
  • 3D Gaussian Splatting（arXiv 2308.04079）
  • Instant-NGP（NVlabs 开源）
  • NVIDIA DLSS（神经超分落地代表）
